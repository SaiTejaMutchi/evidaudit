Why outcome-only tests miss production failures

An agent can return the right decision today while relying on a wrong extracted fact. Standard output checks pass until a policy rule changes.

1. Extracted Fact prohib_export = FALSE The LLM misreads evidence E2. Ground truth is TRUE (restricted).
2. Masked Decision Gate returns ALLOW An active waiver (ov_waiver = TRUE) masks the mistake. Output evals score 100%.
3. Policy Change Waiver is revoked Security updates the rule: ov_waiver changes from TRUE to FALSE.
4. Unsafe Approval Still returns ALLOW Because prohib_export was saved as FALSE, the restricted action goes through.
5. EvidAudit Caught before deploy Flags concealed_corruption, pinpoints prohib_export, and verifies BLOCK on fix.

    Built for engineers shipping action-authorizing AI agents
    
          
    
            Pipeline position: Upstream extraction -> Structured facts -> Decision engine -> Action.
            EvidAudit checks the structured facts and tests how downstream decisions behave when policies change.
          
    
        
    
        
    
          
    
            
    Procurement & Export Approval Agents
    
            
    Verify that an extracted sanction or export restriction is accurate even when an active waiver masks the error today.
    
          
    
          
    
            
    Insurance Eligibility Extraction
    
            
    Catch inverted eligibility conditions that pass JSON Schema validation and produce the right claim outcome until policy rules tighten.
    
          
    
          
    
            
    Payment Authorization Pipelines
    
            
    Test date-cutoff and grace-window rules under fresh re-extraction so expired authorizations do not slip through after a policy update.

    Run deterministic YAML regression suites before changing an LLM, editing an extraction prompt, revoking exceptions, or modifying agent permissions.
    
          
    
        
    
      
    
    
    

    
    
    
      
    
        
    
          
    How EvidAudit works
    
          
    Five deterministic steps that separate intermediate extraction accuracy from final decision accuracy.
    
        
    
        
    
          
    
            01
            Provide Evidence & Facts
            Pass extracted fields, citation IDs, and expected ground truth via Python or YAML.
          
    
          
    
            02
            Audit Intermediate State
            Compare every extracted predicate against reference facts even when the final decision matches.
          
    
          
    
            03
            Test Policy Transitions
            Simulate waiver revocations, date-cutoff shifts, and fresh-regeneration updates.
          
    
          
    
            04
            Pinpoint & Verify Fix
            Isolate the exact wrong field and verify that fixing it restores the safe outcome.
          
    
          
    
            05
            Gate in CI/CD
            Run checks in pytest, GitHub Actions, Promptfoo, or DeepEval before deployment.

            Core API: Auditor
            
    Agent Authorization Gates
    
            
    Audit prerequisites, prohibitions, and authority-ranked overrides in deterministic v2-strict gates.
    
          
    
          
    
            YAML Runner: examples/payment_expiry.yaml
            
    Financial & Payment Expiry
    
            
    Catch date-comparison bugs (2026-11-25 > 2026-11-20) missed by frozen replay tests.
    
          
    
          
    
            Integrations: Pydantic / LangChain
            
    Structured Document Extraction
    
            
    Audit schema-valid JSON outputs against source documents to catch inverted booleans and missing conditions.
    
          
    
          
    
            Core API: test_override_revocation
            
    Policy-Driven Automation
    
            
    Stress-test rule updates against existing agent extractions before shipping policy changes.
    
          
    
          
    
            Checker: v2-strict Grounding
            
    Evidence-Grounded Decisions
    
            
    Fail closed with ABSTAIN when an agent cites a policy ID (P1) instead of a factual evidence passage.
